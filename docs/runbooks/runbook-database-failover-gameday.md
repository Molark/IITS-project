# Runbook: Аварийное переключение БД (Сценарий GameDay)

**Триггер:** Учебный сценарий Chaos GameDay или реальный отказ основного ЦОД.
**Опора:** ADR-011 (Тёплый резерв, RTO 30 мин, RPO 0 для `БД выдачи` и `БД оплаты`).

## Диагностика
1. Подтвердить отказ: алерты недоступности основного writer, статус репликации.
2. Убедиться, что это не ложное срабатывание сети.

## Смягчение
1. Выполнить fencing основного writer (заблокировать запись, чтобы избежать split-brain).
2. Переключить DNS/балансировщик на резервный ЦОД.
3. Подтвердить, что резервная БД поднята в режиме единственный writer.
4. Запустить replay событий из outbox для восстановления целостности.

## Проверка
1. Запись и чтение работают.
2. RPO = 0 (нет потерянных подтверждённых записей).
3. RTO < 30 минут.

## Эскалация
При рассинхронизации данных или потере фактов -> ручной разбор с архитектором данных и остановка новых операций до сверки.
