# Разбор инцидента: Таймаут провайдера оплаты (SEV-2)

- **Резюме:** 15 ноября, 14:02–14:41 (39 мин). Рост задержек `Банка` привёл к недоступности приёма новых платежей.
- **Влияние:** ~1200 операций задержаны, сгорело 15% бюджета ошибок SLO "Результат оплаты".
- **Хронология:**
  - 14:02: `Банк` начал отвечать за 15+ секунд.
  - 14:06: Сработал алерт по бюджету SLO.
  - 14:09: Дежурный подтвердил инцидент, назначен Руководитель.
  - 14:30: Ручное переключение на резервный канал по Runbook (после согласования).
  - 14:41: Метрики вернулись в норму.
- **Причины (5 почему):**
  1. Почему переключили так поздно? → Runbook требовал ручного согласования.
  2. Почему требовалось согласование? → Команда боялась переключать без проверки.
  3. Почему не проверяли? → Нет регулярных учений и тестового контура для отработки fallback.
  4. Почему не сработал Circuit Breaker автоматически? → Порог срабатывания был настроен только на ошибки (5xx), но не на рост latency.
- **Что сработало хорошо:** Деградация (запрет новой НП-выдачи в `Сервисе выдачи`) защитила от повторных списаний.
- **Действия:**
  | Действие | Тип | Владелец | Срок |
  |---|---|---|---|
  | Настроить алерт на рост задержки (latency) провайдера, а не только на ошибки | Обнаружение | Руководитель Интеграций | 1 неделя |
  | Автоматизировать переключение на резервный канал при размыкании выключателя | Предотвращение | Руководитель Платформы | 2 недели |
  | Провести ежемесячные учения по переключению (Chaos GameDay) | Проверка | Команда эксплуатации | Ежемесячно |
