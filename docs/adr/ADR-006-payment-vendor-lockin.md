# ADR-006. Стратегия интеграции с провайдером оплаты и план выхода

**Статус:** предложено

**Связи:** FR-02, FR-05, NFR-01, NFR-02, ADR-003, ADR-005; C2: Адаптер оплаты (ACL), Сервис выдачи

## Контекст

Для обработки оплат при получении (НП) мы используем внешнего провайдера эквайринга. 
Риски: провайдер может повысить комиссию, изменить API или его доступность может упасть. Синхронный вызов к провайдеру должен укладываться в 2 секунды (NFR-01), а при потере связи точка должна работать до 4 часов (NFR-02). Прямая зависимость кода Сервиса выдачи от кодов ответов конкретного банка создаёт Vendor Lock-in и риск каскадных сбоев.

## Варианты

* **A.** Прямой вызов API банка из Сервиса выдачи.
* **B.** Вызов через Anti-Corruption Layer (ACL) с таймаутами, фоновым опросом статуса и формальным планом выхода (Exit Plan).
* **C.** Два провайдера оплаты за ACL с горячим резервированием (active-active).

| Критерий | Вес | A | B | C |
|---|---|---|---|---|
| Изоляция сбоев и соблюдение NFR-01 (≤ 2 с) | 3 | 1 | 5 | 5 |
| Скорость и стоимость замены провайдера | 3 | 1 | 4 | 3 |
| Сложность реализации и поддержки | 2 | 5 | 4 | 1 |
| Отсутствие Vendor Lock-in (своя модель данных) | 2 | 1 | 5 | 5 |
| **Итого (макс. 50)** | | 22 | **46** | 37 |

## Решение

Вариант B. Провайдер оплаты подключается только через контейнер «Адаптер оплаты» (ACL). Сервис выдачи не знает о кодах банка, он работает только с нашими статусами: `paid`, `declined`, `unknown`. При сбое адаптер использует таймаут 1.5 с и фоновый опрос, а не блокирует выдачу.

## Последствия

**Плюсы:** Замена провайдера потребует изменений только внутри Адаптера, ядро системы не пострадает. Сбои и задержки банка изолированы и не блокируют АРМ оператора. Все исторические платежи хранятся в нашей БД в нормализованном виде.

**Минусы:** Требуется поддержка таблицы трансляции статусов и эмулятора для тестирования сетевых сбоев. Нет горячего резервирования: при полном отказе провайдера оператор действует по ручному регламенту (проверка по документу).

## Пересмотр

Если провайдер поднимает цену > 20% или SLA доступности падает ниже 99.5% в течение 2 месяцев, мы активируем план выхода: разработка нового Адаптера под API альтернативного провайдера (оценка: 3 недели) с параллельной работой через Feature Flag.
