# ADR-004. Статус оплаты определяет только сервер

**Статус:** предложено

**Связи:** T-02, T-06, FR-01, FR-05, NFR-01; C2: Сервис выдачи, Адаптер оплаты

## Контекст

Самая дорогая угроза — выдача заказа без оплаты (T-02, T-06): товар уже у клиента, вернуть его нельзя. АРМ стоит на точке, где за тем же компьютером может сидеть продавец магазина, а в пик оператор хочет выдать заказ, не дождавшись банка. Если сервер поверит статусу «оплачено», который пришёл от АРМ, заказ можно выдать без денег.

## Варианты

* **A.** АРМ передаёт статус оплаты с терминала, сервис выдачи ему доверяет.
* **B.** Сервис выдачи берёт статус только у адаптера оплаты, а адаптер узнаёт его у банка по ID операции через mTLS.
* **C.** Как B, плюс старший смены вручную подтверждает каждую оплату.

| Критерий | Вес | A | B | C |
|---|---|---|---|---|
| Нельзя выдать без оплаты (FR-01) | 3 | 1 | 5 | 5 |
| Скорость выдачи в пик (NFR-01) | 2 | 5 | 4 | 1 |
| Просто сделать | 1 | 5 | 3 | 3 |
| **Итого (макс. 30)** | | 18 | **26** | 20 |

## Решение

Вариант B. Статус и сумма из запроса АРМ игнорируются, кнопка «Выдать» на сервере разрешается только при статусе «оплачено» от адаптера оплаты.

## Последствия

**Плюсы:** подделка в АРМ или в запросе не позволяет выдать заказ.

**Минусы:** выдача с оплатой зависит от связи с банком; без связи она запрещена (ADR-002). Нужен spike: можно ли получить статус оплаты по ID.

## Пересмотр

Если spike покажет, что банк не отдаёт статус по ID, перейдём на подписанные уведомления банка (webhook).
