# ADR-002. База данных

**Статус:** предложено

**Связи:** FR-01, FR-05, FR-06, NFR-02, NFR-03, NFR-04; C2: АРМ оператора, БД выдачи, БД приёмки, БД сверки

## Контекст

Нельзя выдать заказ без оплаты (FR-01). Нельзя записать одну выдачу дважды (NFR-04). Точка работает без связи до 4 часов (NFR-02), и после этого все события доходят до сервера (NFR-03). В конце смены нужен реестр «заказ — оплата — выдача» (FR-06).

## Варианты

* **A.** PostgreSQL на сервере, IndexedDB в АРМ.
* **B.** MongoDB на сервере, IndexedDB в АРМ.
* **C.** CouchDB на сервере, PouchDB в АРМ (у них есть встроенная синхронизация без связи).

| Критерий | Вес | A | B | C |
|---|---|---|---|---|
| Надёжные проверки: нет выдачи без оплаты и нет дублей (FR-01, NFR-04) | 3 | 5 | 3 | 2 |
| Работа без связи (NFR-02, NFR-03) | 3 | 3 | 3 | 5 |
| Удобно собирать реестр смены (FR-06) | 2 | 5 | 3 | 2 |
| Опыт команды, бесплатная лицензия | 1 | 5 | 3 | 2 |
| **Итого (макс. 45)** | | **39** | 27 | 27 |

## Решение

Вариант A: PostgreSQL на сервере (своя БД у каждого сервиса) и IndexedDB в АРМ. Выдача с оплатой при получении без связи запрещена.

## Последствия

**Плюсы:** проверки и защита от дублей работают в одной транзакции. Реестр смены собирается обычным SQL. Команда знает PostgreSQL.

**Минусы:** отправку событий из АРМ после восстановления связи пишем сами. Нужно проверить, что IndexedDB не теряет данные при перезапуске браузера.

## Пересмотр

Если IndexedDB на компьютерах точек будет терять данные, перейдём на десктоп-приложение с локальной базой.
