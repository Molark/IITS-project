# Трансляция моделей внешних систем (Anti-Corruption Layer)

Этот документ описывает, как Адаптеры (ACL) переводят чужие модели данных в наши доменные статусы, не пропуская чужую логику в ядро системы.

## 1. Адаптер оплаты (Банк → Наша система)

Коды и форматы банка не выходят за пределы адаптера. В БД выдачи и в событиях Kafka используются только наши статусы.

| Понятие в нашей модели | Код/статус у провайдера (пример) | Действие Адаптера (ACL) |
|---|---|---|
| `paid` (Подтверждено) | `00`, `000` (Успех) | Прямая трансляция. |
| `declined` (Отклонено) | `05` (Отказ), `51` (Недостаточно средств) | Трансляция в `declined`. Причина записывается в лог адаптера для оператора. |
| `unknown` (Неизвестно) | `91` (Банк недоступен), Таймаут, HTTP 504 | Трансляция в `unknown`. Адаптер запускает фоновый опрос статуса по ID операции (до 60 с). |
| Незнакомый код | Любой новый код, не описанный в контракте | Трансляция в `unknown` + алерт команде разработки. **Система не падает.** |
| Сумма и время | Сумма в копейках строкой, локальное время терминала | Преобразование: сумма в `integer` (копейки), время в `UTC`. |

## 2. Адаптер ERP (Наша система → Внешняя ERP)

ERP работает в пакетном режиме и имеет свою модель документов. Мы не пишем в таблицы ERP напрямую.

| Наша сущность (Событие) | Документ в ERP | Правила трансляции |
|---|---|---|
| `ShiftClosed` (Итоги смены) | Документ "Отчёт о розничных продажах" | Агрегация всех событий `OrderIssued` и `PaymentStatusChanged` за смену. Ключ синхронизации: `shift_id`. |
| `OrderReturned` (Возврат) | Документ "Возврат от покупателя" | Создаётся только если исходная продажа была проведена в этой ERP. Связь по `order_id`. |

**Правило:** Если ERP недоступна, Адаптер ставит пакет в локальную очередь и повторяет отправку в следующую смену, не блокируя работу ПВЗ.
