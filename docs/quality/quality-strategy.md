# Стратегия качества

Сценарий: выдача заказа с оплатой при получении (НП).

Тесты берём из [требований](../04-requirements-and-prototype.md), [реестра угроз](../security/threat-model.md), [матрицы доступа](../security/access-and-audit.md) и контрактов ([openapi](../../openapi), [asyncapi](../../asyncapi)).

## 1. Главные риски

| Риск | Требование / угроза | Чем проверяем |
|---|---|---|
| Выдача без оплаты | FR-01, T-02 | E2E-01, компонентный тест подмены суммы |
| Двойное списание | FR-05 | E2E-01 |
| Потеря выдачи после офлайна | NFR-03 | E2E-02 |
| Смена не сходится | FR-06, DQ-03 | E2E-03 |
| Действие не по правам | T-03, T-04 | E2E-04, тесты матрицы доступа |

## 2. Уровни тестов

| Уровень | Что проверяем | Пример |
|---|---|---|
| Модульный | Правила и расчёты | Сумма к оплате берётся из заказа; незнакомый код банка → `unknown` |
| Компонентный | Один сервис через API, остальное — заглушки | Повторная выдача → 409 |
| Контрактный | Совместимость по OpenAPI и AsyncAPI | Сверка читает `OrderIssued` v1 после изменений в Сервисе выдачи |
| Интеграционный | Работа с настоящей БД и Kafka | Outbox отправляет событие только после коммита |
| E2E | Результат во всех системах | [Каталог E2E](./e2e-catalog.md), 4 сценария |

Нефункциональные проверки:

| Проверка | Что | Откуда |
|---|---|---|
| Нагрузка | Ответ на запуск оплаты ≤ 2 с в 95% случаев при загруженной кассе | NFR-01 |
| Офлайн | 4 часа без связи, потом синхронизация без потерь | NFR-02, NFR-03 |
| Доступ | Каждая ячейка матрицы доступа: «можно» и «нельзя» | Матрица доступа |
| Логи | В логах нет ФИО, полного телефона и токенов | T-07 |

## 3. Среды

| Среда | Для чего | Что внутри |
|---|---|---|
| Локальная | Модульные и компонентные | Заглушки из OpenAPI |
| Эфемерная в CI | Тесты на каждый pull request | PostgreSQL, Kafka и эмуляторы в контейнерах |
| Stage | E2E, контракты, доступ | Все сервисы, эмуляторы, песочницы банка и маркетплейса |
| Предпрод | Нагрузка | Настройки как в продуктиве |
| Продуктив | Smoke после релиза | Реальные данные |

Внешние системы:

| Система | Песочница | Эмулятор |
|---|---|---|
| Банк | Тестовые карты | Оплачено, отказ (`05`, `51`), молчание, задержка, незнакомый код |
| Маркетплейс | Тестовый кабинет | Ответ 5xx, медленный ответ |
| ERP | — | Недоступна (окно обслуживания), повторный пакет |
| SMS-шлюз | — | Заглушка, хранит код для теста |

Время в сервисах берётся через отдельный объект «часы», поэтому опрос банка 60 с и офлайн 4 ч проверяем сдвигом часов.

## 4. Ворота качества

| Этап | Что запускаем | Стоп, если |
|---|---|---|
| Pull request | Модульные и контрактные, до 10 минут | Упал тест или сломан контракт |
| Сборка | Компонентные и интеграционные | Упал тест |
| Stage | E2E и тесты доступа | Не прошёл сценарий или ветка |
| Предпрод | Нагрузка NFR-01 | p95 оплаты > 2 с |
| Продуктив | Smoke и метрики | Метрики хуже порога — откат |
